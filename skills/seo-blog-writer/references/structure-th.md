# มาตรฐานการเขียนบทความ SEO ไทย (อิง Backlinko + Ahrefs + Google Helpful Content)

writer ต้องเขียนตามนี้ทุกบทความ — gate จะ warn ถ้าไม่มีลิสต์/ย่อหน้ายาวเกิน

## 0. จังหวะเป้าหมาย (เขียนให้ได้แบบนี้เสมอ)
```
## SEO ทำเองได้ไหม หรือต้องจ้าง

<ย่อหน้า 1: 1–3 ประโยคสั้น>

<ย่อหน้า 2: 1–3 ประโยคสั้น>

<ประโยคนำลิสต์:>

- จุดที่ 1 (สั้น actionable)
- จุดที่ 2
- จุดที่ 3
- จุดที่ 4

<ย่อหน้าปิดหัวข้อ 1–2 ประโยค>
```
ทุกย่อหน้า **คั่นด้วยบรรทัดว่าง** (1 แนวคิด/ย่อหน้า, สั้น 1–3 ประโยค) + มี **bullet** สำหรับชุดที่ทำเป็นข้อได้ (การเยื้องบรรทัดแรกเป็น CSS ของเว็บเอง ไม่ต้องทำใน markdown)

## 1. โครงสร้าง (scannable)
- **H1 เดียว** = ชื่อบทความ มี keyword หลัก
- intro 2–4 ประโยค ตอบ intent ทันที + **ใส่ keyword หลักใน ~100 คำแรก** (ธรรมชาติ ไม่ยัด)
- H2/H3 เป็นชั้น ไม่ข้าม — H2 สื่อหัวข้อย่อยชัด (คนสแกนหัวข้อก่อนอ่าน)
- ปิดด้วยสรุป + CTA ไป pillar/contact

## 2. รูปแบบให้อ่านง่าย (บังคับ — จุดที่เคยพลาด)
- **ต้องมี bullet/numbered list อย่างน้อย 1 ชุด** (ขั้นตอน/ข้อดี/เช็คลิสต์/เปรียบเทียบ) — gate warn ถ้าไม่มี
- **ห้ามใช้ markdown table** (`| ... | --- |`) — renderer เว็บไม่รองรับ GFM table จะโชว์ pipe ดิบ. เทียบของหลายอย่าง → ใช้ **หัวข้อย่อย (H3) + bullet** หรือ bullet ซ้อน แทน เช่น `**ตัวเลือก A** — ข้อดี/เหมาะกับ` (gate warn ถ้าเจอ table)
- **แตกย่อหน้าจริง**: เว้นบรรทัดว่างระหว่างทุกย่อหน้า (markdown ต้องมีบรรทัดว่างถึงจะขึ้น `<p>` ใหม่) — 1 แนวคิด = 1 ย่อหน้า ห้ามเขียนรวดติดกัน — gate warn ถ้าแตกย่อหน้าน้อยไป (~1 ย่อหน้า/120 คำ)
- **ย่อหน้าสั้น** 2–4 บรรทัด ห้ามกำแพงตัวอักษร — gate warn ถ้าย่อหน้า > ~700 ตัวอักษร
- ภาษาง่าย เลี่ยงศัพท์ใหญ่เกินจำเป็น (Ahrefs: "big words mask little thoughts")

## 2b. เน้นข้อความ (emphasis) — ทำได้แต่ระวัง
- **`**ตัวหนา**` เน้นจุดสำคัญ/คำที่อยากให้จำ** — ใช้ **เฉพาะคำ/วลีสั้น** ไม่ใช่ทั้งประโยค/ทั้งย่อหน้า (gate warn ถ้า bold ยาว >120 ตัว หรือ >18 จุด — Google มองว่า over-format = spam)
- `*ตัวเอียง*` ใช้กับคำศัพท์/ชื่อเฉพาะ พอประมาณ
- callout/กล่องสำคัญ → `> ข้อความ` (blockquote) หรือบรรทัด `💡 **ข้อควรรู้:** ...` — เด้งสายตาได้โดยไม่พึ่งของที่ render ไม่ได้
- ❌ **ห้าม** `==highlight==`, `<mark>`, `<span style=...>`, สีตัวอักษร, ตัวบาง (font-weight) — renderer เว็บไม่รองรับ (จะโชว์โค้ดดิบ) + ตัวบางเป็น CSS ของเว็บ ทำใน markdown ไม่ได้ (gate warn ถ้าเจอ)
- เน้นเพื่อ "ผู้อ่านสแกนเจอแก่น" ไม่ใช่ตกแต่ง — bold ทุกคีย์เวิร์ด = เสีย SEO

## 3. ความยาว (comprehensive ไม่ใช่ตัวเลขตายตัว)
- Google ยืนยัน: **ไม่มี word count ที่ Google ชอบ** — เขียนครบ intent คือเป้า ไม่ใช่ยัดให้ถึงเลข
- ครอบหัวข้อจน "ผู้อ่านไม่ต้องเสิร์ชต่อ" (Backlinko: long-form ที่ comprehensive ติดดีกว่า เพราะครบ ไม่ใช่เพราะยาว)
- `word_count_min` = กัน thin (พื้น) ไม่ใช่เป้า — เกินได้ถ้ามีค่า ห้ามยืดน้ำ/ฟิลเลอร์

## 4. Search intent (สำคัญสุด)
- ดู SERP keyword ก่อน: how-to / listicle / นิยาม / เปรียบเทียบ → เขียนให้ตรงรูปแบบนั้น
- ตอบ People-Also-Ask จาก research เป็นหัวข้อย่อย/FAQ (ดึง snippet + ตรง intent)

## 5. E-E-A-T / People-first (Google)
- เขียนเพื่อคน ไม่ใช่เพื่อบอต/ยอด — ห้ามสรุปลอกคนอื่นไม่เพิ่มค่า
- ใส่ประสบการณ์/มุมจริงของแบรนด์ = trust (Google: trust สำคัญสุดใน E-E-A-T)
- ไม่สัญญาสิ่งที่ไม่มีคำตอบ ไม่ปลอม freshness

## 6. Keyword & internal link
- keyword หลักใน: H1, ~100 คำแรก, H2 ≥1 จุด, ธรรมชาติทั้งบทความ — **ห้าม stuffing**
- internal link: gate บังคับ ≥2, **แนะนำ 4–5**/บทความ, ≥1 ไป pillar — anchor สื่อความ ไม่ใช่ "คลิกที่นี่"

## 7. ไทยโดยเฉพาะ
- ไทยไม่เว้นวรรคระหว่างคำ → heading/lists/ย่อหน้าสั้น ช่วยสายตา (สำคัญกว่าอังกฤษ)
- ประโยคยาว-สั้นสลับจังหวะ เว้นวรรคถูกตำแหน่ง อ่านลื่น
- โทนตาม `config.voice` + `voice/style-notes.md` (ดู [[humanize-th]])
- เลี่ยงสำนวน AI ซ้ำ, ไม่อ้างวิจัยลอย, ใช้ "สัปดาห์" ไม่ใช่ "อาทิตย์", ไม่ "555"
